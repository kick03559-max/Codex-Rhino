# Codex + Rhino 日常使用教程

## 1. 每次任务的标准顺序

```text
启动 Rhino → 启动 Rhino MCP 脚本 → 启动/重启 Codex
→ 只读读取场景 → 说明建模方案 → 等待确认
→ 执行一小步修改 → 再读取验证 → 保存版本
```

不要一开始就要求 AI 一次性创建大量复杂几何。先建立上下文，再分步执行，模型更容易验收和恢复。

## 2. 第一步：读取场景

推荐提示词：

```text
请读取 Rhino 当前场景，只报告：
1. 当前对象总数；
2. 图层名称和各层对象数量；
3. 主要几何类型；
4. 整体边界框；
5. 当前单位。

本次只读，不要选择、创建、删除、移动、修改或保存任何对象。
```

如果需要更详细的对象上下文：

```text
请读取当前 Rhino 场景中由 MCP 创建的对象元数据，报告对象名称、图层、类型、边界框和描述；不要修改模型。
```

## 3. 第二步：提出建模方案

给出参考图后，不要直接说“照图建模”而不提供验收标准。至少明确：

- 目标对象是什么；
- 尺寸是否为实测值，还是按图估算；
- 坐标原点和方向；
- 单位；
- 图层与对象命名；
- 是否保留当前场景；
- 是否需要等待确认；
- 完成后检查什么。

模板：

```text
根据这张参考图准备 Rhino 建模方案。

目标：<对象名称和用途>
单位：毫米。
尺寸：<实测尺寸；如果没有实测尺寸，先列出估算参数，不要直接执行>
坐标：XY 为水平面，Z 轴向上，放置在 <基准点>。
图层：<图层名>。
保留现有对象：是，不删除、不覆盖。
输出：先说明构件、参数、建模顺序和不确定项，等待我确认后再创建。
```

## 4. 第三步：执行写操作

确认方案后，使用分阶段提示：

```text
按已确认参数执行第一阶段：只创建主体白模和基础图层。
执行前再次列出将创建的对象和数量；不要删除已有对象。
完成后读取场景，报告新对象数量、图层、边界框和几何类型。
```

第二阶段再处理：

- 圆角、倒角、布尔和细节；
- 对象颜色或材质；
- 纹理映射；
- 标注、编号和资料表。

## 5. 第四步：验收

每一次写操作后都要求：

```text
请重新读取 Rhino 场景，核对：对象数量、图层、对象名称、主要几何类型、整体边界框和单位。只报告实际结果，并指出与目标参数的差异。
```

如果视口外观重要，再要求：

```text
请捕获当前 Rhino 视口用于检查，只读，不修改模型；显示对象，不显示额外标注。
```

## 6. 第五步：保存和版本管理

保存前使用明确文件名，例如：

```text
请将当前 Rhino 文件保存为：
D:\项目目录\模型名_v001.3dm
保存后确认文件存在，并报告文件路径。不要覆盖其他版本。
```

建议版本顺序：

```text
v001_白模
v002_尺寸校正
v003_倒角细节
v004_材质贴图
v005_最终渲染
```

## 7. 当前茶几案例的完整提示词

```text
在 Rhino 当前文档中创建一张圆形实木茶几白模。

单位：毫米；XY 为水平面，Z 轴向上。
放置：茶几中心为 X=1200，Y=0，底面 Z=0，避开现有画框模型。
尺寸：桌面直径 1200，桌面厚度 100，总高度 520，桌腿高度 420，桌腿直径 260。
构件：1 个圆形桌面，3 个等直径圆柱桌腿，前方一条、后方左右各一条；不添加参考图中不可见的横撑和五金。
图层：CoffeeTable_Top、CoffeeTable_Legs、CoffeeTable_Details、CoffeeTable_Material、CoffeeTable_Reference。
命名：CoffeeTable_Top、CoffeeTable_Leg_Front、CoffeeTable_Leg_BackLeft、CoffeeTable_Leg_BackRight。
现有画框必须保留，不删除、不覆盖。
执行前先说明方案；完成后报告对象数量、图层和边界框。
```

## 8. 读取已创建对象

```text
请只读取名称匹配 CoffeeTable_* 的 Rhino 对象，报告每个对象的名称、图层、类型、边界框、材质路径和 UserText；不要修改模型。
```

## 9. 什么时候必须让 AI 停下来

- 参考图没有尺寸，且不同尺寸会影响结果；
- 需要删除或覆盖已有对象；
- 需要移动、重命名或批量修改不确定范围的对象；
- 布尔运算、网格转换或复杂脚本可能改变拓扑；
- 需要上传文件、发布 GitHub 或共享外部数据；
- 需要使用个人配置、密钥或登录状态。
