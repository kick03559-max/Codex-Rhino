# 故障排查与安全规则

## 1. Codex 看不到 `rhino7_mcp`

1. 检查 `C:\Users\<用户名>\.codex\config.toml` 是否存在 `[mcp_servers.rhino7_mcp]`。
2. 检查 `command` 是否指向实际存在的 `reer-rhino-mcp.exe`。
3. 完全重启 Codex Desktop。
4. Rhino 7 必须已经打开并运行 `rhino_script.py`。
5. 使用只读场景查询验证，不要先执行写操作。

## 2. 出现“不支持身份验证”

本机路线是本地 STDIO MCP，不使用 OAuth；“不支持身份验证”不是 Rhino 模型错误。确认：

- Codex MCP 名称为 `rhino7_mcp`；
- 配置使用 `command`，不是 `url`；
- Rhino 侧脚本运行在本机；
- 本地端口为 `127.0.0.1:9876`。

不要把视频中的 `http://localhost:3001/mcp` 与当前 STDIO 桥接混用。

## 3. Rhino 脚本启动失败

- 确认 Rhino 7 路径和脚本路径无误。
- 确认脚本是从 Rhino 内部运行，而不是用普通系统 Python 直接运行。
- 确认没有多个 Rhino MCP 脚本实例同时占用端口。
- 关闭 Rhino 后重新启动，再运行一次脚本。
- 如果错误与图层对象计数或选择属性有关，优先使用资料包中的已验证 `rhino_script.py`，不要混入 Rhino 8 API 写法。

## 4. MCP 连接正常但写操作失败

先缩小任务：

1. 只创建一个 Box 或 Cylinder。
2. 只操作一个图层。
3. 删除材质、布尔、批量对象和 HTML 输出等非必要步骤。
4. 写操作完成后立即读取场景。
5. 复杂任务拆成多个调用。

## 5. Rhino 7 IronPython 执行错误

Rhino 7 使用 IronPython 2.7。避免：

- f-string；
- 类型注解；
- `match/case`；
- walrus 运算符；
- 依赖包装器外部注入的 `rg`、`sc` 或辅助函数。

可靠写法是把所有导入、辅助函数和执行代码放在一个 `main()` 函数内。

## 6. FHL 材质生成失败

1. 用 `--get-config` 检查是否有可用 worker，但不要输出完整 key。
2. 单图请求只使用一个 worker。
3. Images API 失败时重试 Images API，不要切换 Responses。
4. 先降低并发，单张请求重新运行。
5. 成功后保留原始 PNG，并确认实际输出路径。

## 7. Rhino 材质丢失

Rhino 材质记录的是贴图路径。移动资料包后：

1. 打开 Rhino 材质编辑器。
2. 将桌面和桌腿材质的纹理路径重新指定到项目 `资产` 目录。
3. 切换到材质预览或渲染模式检查。
4. 保存一个新版本。

## 8. 安全规则

- 只将 MCP 绑定到本机，不要在没有认证的情况下暴露到公网。
- Codex 配置优先使用 `default_tools_approval_mode = "writes"`。
- 写入前先说明对象数量、图层、单位、坐标和影响范围。
- 默认不删除、不覆盖、不批量重命名既有对象。
- 不把 `config.toml`、API key、`.env` 实际文件、浏览器登录信息、虚拟环境目录上传到 GitHub。
- 复杂修改前先保存 Rhino 版本。
- 参考图无法确认的尺寸要标记为估算，不要伪装成实测值。
