# Codex 与 Rhino 7 本地连接配置

## 1. 连接路线先确认

本机使用的是：

```text
Codex → 本地 STDIO MCP → reer-rhino-mcp → 127.0.0.1:9876 → Rhino 7
```

B 站视频展示的是 RhinoAiMCP + Claude Desktop 的 HTTP 路线，常见地址是 `http://localhost:3001/mcp`。那条路线可用于理解 MCP，但不是本机最终配置。当前电脑使用 Rhino 7，因此采用兼容性更稳定的 `reer-ide/rhino_mcp` 桥接脚本。

## 2. 前置软件

确认以下软件已经安装：

1. Rhino 7，当前路径：`D:\Program Files\Rhino 7\System\Rhino.exe`。
2. Codex Desktop，且可以正常打开和执行任务。
3. Python 3.10 或更新版本。
4. `uv` Python 环境管理器。

如果需要重新安装 Python/uv，请使用官方安装来源；不要从不明下载站获取运行环境。当前资料包不包含完整虚拟环境，因为虚拟环境不适合上传 GitHub。

## 3. 准备 Rhino MCP 源码

资料包中的 `rhino_mcp` 目录包含本机使用的源码副本：

```text
rhino_mcp\rhino_script.py
rhino_mcp\main.py
rhino_mcp\requirements.txt
rhino_mcp\pyproject.toml
```

在新电脑上可以把资料包复制到固定目录，例如：

```text
D:\20260525\2026项目汇总\AIGC\CODEX
```

实际使用时，所有配置路径都必须改成新电脑上的绝对路径。

## 4. 创建 Python 环境

在 PowerShell 中执行以下步骤。目录不存在时创建；如果环境已经存在，不要重复删除，先直接验证：

```powershell
cd "D:\20260525\2026项目汇总\AIGC\CODEX\rhino_mcp"
uv venv "D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp_env" --python 3.10
uv pip install --python "D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp_env\Scripts\python.exe" -r requirements.txt
```

验证：

```powershell
"D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp_env\Scripts\python.exe" --version
Test-Path "D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp_env\Scripts\reer-rhino-mcp.exe"
```

两个检查分别应输出 Python 版本和 `True`。

## 5. 启动 Rhino 侧脚本

1. 打开 Rhino 7。
2. 在 Rhino 命令行执行：

```text
_-RunPythonScript "D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp\rhino_script.py"
```

3. 等待脚本启动本地服务。当前桥接端口是 `127.0.0.1:9876`。
4. 保持 Rhino 运行，不要在 Codex 调用期间关闭 Rhino 或阻塞 Rhino 的 Python 主线程。

如果 Rhino 7 的 Python 编辑器可用，也可以从 `Tools → Python Editor` 打开 `rhino_script.py` 并运行。命令行方式更适合固定流程。

## 6. 配置 Codex

打开用户级配置文件：

```text
C:\Users\<你的用户名>\.codex\config.toml
```

把 [配置模板](../配置模板/codex-mcp-config.example.toml) 中的服务器段复制进去。当前电脑实际配置的核心内容是：

```toml
[mcp_servers.rhino7_mcp]
command = 'D:\20260525\2026项目汇总\AIGC\CODEX\tools\rhino_mcp_env\Scripts\reer-rhino-mcp.exe'
startup_timeout_sec = 20
tool_timeout_sec = 120
default_tools_approval_mode = "writes"
```

注意：上面代码中的 `tool_timeout_sec` 行必须与其他配置行一样位于段落内部；复制时不要把 Markdown 说明一起复制进 TOML。

参数含义：

- `command`：MCP server 的绝对可执行文件路径。
- `startup_timeout_sec`：给桥接服务启动的时间。
- `tool_timeout_sec`：给 Rhino 代码执行和视口捕获的时间。
- `default_tools_approval_mode = "writes"`：写入或修改模型的工具需要审批，适合日常使用。

## 7. 重启和验证

1. 完全退出并重新打开 Codex Desktop。
2. 确认 Rhino 7 仍在运行，且 Rhino 侧脚本没有报错。
3. 在 Codex 中查看 MCP 状态；如果使用 CLI，可运行：

```powershell
codex mcp list
```

4. 第一次只做只读测试：

```text
请读取 Rhino 当前场景，只报告对象数量、图层、主要几何类型和整体边界框，不要修改模型。
```

5. 只有只读测试成功后，才进行建模或材质写入。

## 8. 关闭流程

1. 先保存 Rhino 文件。
2. 再关闭 Rhino 7。
3. 如果要关闭 MCP 桥接，先结束 Rhino 侧脚本，再关闭 Codex；不要在脚本仍占用端口时重复启动多个桥接。
